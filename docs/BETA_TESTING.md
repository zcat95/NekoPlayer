# 2.6.0-beta.1 手机测试

直接覆盖安装 beta APK，沿用以前的签名、包名和应用数据。Android 12 及以上可用。

这版加入多目录、双击点赞和手机诊断，同时调整播放器缓冲、预览内存和后台预读。云端已做编译和逻辑检查，真实手机上的流畅度、内存与耗电还需要这一轮数据确认。

## 最省事的反馈方法

1. 打开 **设置 → 性能诊断 → 开始新记录**。
2. 返回首页，正常刷 **5 分钟**。期间试几次快速连划、双击点赞、长按加速，以及长按后直接滑动。
3. 关闭“后台播放”，切到桌面放 **2 分钟**，再回来刷 **3 分钟**。
4. 回到 **性能诊断 → 停止记录 → 复制报告摘要**。
5. 把摘要直接粘贴到聊天里，再补一句哪里不对、做了什么操作。全程用手机即可。

摘要包含机型、系统、版本、首帧回调耗时、进程内存、CPU、缓冲和丢帧等数据。不需要自己分析数值。

## 如果可以发文件

停止记录后点 **保存报告到文件**，在系统选择器中存到“下载”。文件名类似：

```text
NekoPlayer-2.6.0-beta.1-diagnostics.json
```

通过聊天的附件按钮上传这个 JSON；也可以点 **分享报告**，从手机分享菜单发送。完整 JSON 比摘要多一些时间线和采样信息，更方便定位问题。

如果手机暂时找不到文件上传入口，先发复制的摘要就够了，JSON 留在下载目录即可。

## 多目录怎么试

- 进入 **设置 → 视频目录**，原先选的目录应当还在。
- 添加第二个视频目录，确认两边的视频都能播放。
- 关掉其中一个目录的“参与播放”，确认它的视频从首页和收藏播放队列暂时退出；重新开启后再确认收藏仍在。
- 关闭并重开应用，确认目录列表和开关状态保留，启动仍在首页。
- 如果某个目录读不到，在目录管理里对它单独“重新授权”；其他可读目录应继续可用。

每个目录只扫描直接包含的视频，子目录需要单独添加。移除目录只移除授权列表条目，原视频、收藏和已看记录保留。

## 手势怎么试

- 单击：暂停／继续。
- 双击：点赞。连续双击已经点赞的视频，也应保持点赞。
- 长按：临时 2 倍速，触发时轻震一次。松手、上下滑、左右切页或进入设置后应恢复。
- 全局 2 倍速开启时，不重复触发临时加速震动。
- 双击不再改画面比例；画面裁切在设置里调整。

如果有误触，告诉我“先按住多久、往哪个方向滑、预期什么、实际发生什么”。能稳定重现的话，附一段十几秒的录屏也很有帮助。测耗电的那一轮先不要录屏，以免增加额外耗电。

## 想再测耗电的话

另开一轮记录，正常刷 **20 分钟**。尽量保持亮度、音量一致，期间不要充电。

结束后停止记录，发摘要或 JSON。若手机系统能看到 Neko Player 的应用耗电页面，也可补一张截图，并说明页面统计的时间范围。后台播放可以再单独测一轮，注明开启或关闭即可。

报告中的电量变化是整机数据，受屏幕和其他应用影响，不能直接当作 Neko Player 单独耗电。部分手机不开放电荷计数，这一项为空也正常。诊断采样本身有少量开销；只有开始记录后才运行，后台采样会降低频率，系统休眠也可能延迟采样。

## 遇到黑屏或闪退

记下大概发生时间、当时做的操作。重新打开应用后，先去性能诊断导出上一份报告，暂时不要开始新记录，以免替换它。Java 层未捕获异常会尽量保存错误类型和代码堆栈；系统杀进程或原生层崩溃通常只能保留最后一次采样，需要同时描述现象。

报告只在本机保存，不包含视频内容、视频文件名或目录路径，不自动上传；由你选择复制、保存或分享。记录时长约 30 分钟后会自动结束，Android 休眠可能延迟结束操作。

beta 版本号高于 2.5.1，Android 不能直接用旧 APK 覆盖降级。遇到问题先保留应用和报告，我会给更高版本的修复包，避免卸载丢失应用内数据。
